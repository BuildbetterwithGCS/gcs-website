Scripted acceptance sequence

  1. Create both synthetic tenants with separate identities and sessions. Confirm pending or unverified entitlement grants no module access.
  2. Activate only the approved test entitlement fixture. Confirm unselected modules remain denied and revocation removes access.
  3. Run cross-tenant read and write attempts for dashboards, leads, jobs, work orders, punches, leave, invoices, documents, assistant previews, and any cursor or export.
  4. Complete Tenant A administrator, manager, and employee journeys. Repeat unauthorized actions from the wrong role and confirm no mutation occurs.
  5. Run the synthetic work order, time punch, leave review, invoice-status, and safe asset-import journeys. Capture exact pass/fail evidence.
  6. Attempt every currently missing module. Record a tested gap; do not substitute a mock screen for an accepted workflow.
  7. Preview the assistant with enabled daily settings and selected topics. Verify stale preference, opt-out, duplicate, synthetic evidence, unknown location, outside-radius, unsafe URL, and cross-tenant cases all fail closed.
  8. Run the bid query without injecting a result. A zero-result response is acceptable; a fabricated bid is not.
  9. Exercise restart, revocation, rollback, and backup/restore evidence for the exact release candidate.
  10. Stop with synthetic data. Real onboarding begins only after independent review, production gates, and explicit approval plus minimum contact/configuration details.

Immediate stop rules

  • Stop if any record, summary, export, link, token, or cursor crosses tenant boundaries.
  • Stop if a pending, stale, canceled, or unverified entitlement grants access.
  • Stop if an employee can approve manager work or access an unassigned record.
  • Stop if a bid or lead appears without retained source and freshness evidence.
  • Stop if email can send without verified credentials, explicit opt-in, deduplication, unsubscribe handling, audit evidence, and an approved test recipient.
  • Stop if any step asks for a bank password, real payment method, customer outreach, bid submission, contract signature, or unsupported live-payroll claim.

Evidence to record

Record the exact commit, CI run, protected deploy ID, synthetic tenant identifiers, role tested, input, expected result, actual result, denial evidence, reviewer, unresolved blocker, rollback result, and exact next action. Never paste secrets, raw provider payloads, real customer data, or sensitive document contents into the checkpoint.
